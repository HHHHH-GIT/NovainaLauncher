# 来源超时修复 · 2026-10-02

## 排查结论

- 超时本身不能证明被反爬或限流；官方明确限流时通常返回 HTTP 429。本次小规模实测官方和 MCIM 都返回 HTTP 200，未复现用户当时的超时，因此不把原因认定为反爬。
- 已确认中文搜索原来最多并发四路，并等待所有请求，最快一路成功也必须等最慢一路；镜像 HTTP 200 后正文卡住也没有官方回退。
- 官方 [Modrinth API 文档](https://docs.modrinth.com/api/) 当前说明每个 IP 每分钟 300 次请求；应用提供独立 User-Agent。没有采用绕过来源限制的方法。

## 修改

- 中文先搜索本地匹配最优的英文关键词，有结果立即展示；其余别名及原中文仅在无结果或失败时依次尝试。英文关键词不受影响。
- 输入改变立即取消旧请求，保留 350ms 防抖；页面恢复避免同时触发立即搜索和防抖搜索。
- JSON 请求统一覆盖响应头、正文读取与解析的来源回退。镜像正文超过 12 秒、断流或无效 JSON 时，Modrinth / 有 Key 的 CurseForge 可转官方；没有 CurseForge Key 时保留镜像真实错误。
- 本地连接预算排队不消耗网络响应头的八秒超时；请求仍有总等待上限及用户取消。
- HTTP 429 按 Retry-After 暂停该主机元数据请求；缺失该头时等待一分钟。不会为了换关键词继续请求已限流的主机。
- 保留元数据新鲜缓存和失败时的旧缓存。日志只记录主机、接口路径、阶段、耗时及状态，不记录查询内容、请求头或 API Key。
- 二进制多连接下载器、手动选 Mod 文件、现有账户和游戏目录沿用现有实现。

## 验证

- 11 项集中检查通过：中文单请求与原文回退、镜像 HTTP 200 正文中断 / 超时回退、429 冷却、用户取消、Key 隔离及既有文件分页。没有重跑游戏安装矩阵。
- 使用修改后的实际代码搜索“钠”：官方约 1.03 秒，MCIM 约 0.20 秒，均一次请求返回 30 项并包含 Sodium；官方 HTTP 200，X-Ratelimit-Remaining 为 299。重复元数据请求从本地缓存读取约 1.5ms。结果在 `artifacts/source-timeout-smoke/result.json`，耗时只代表本次网络。
- 编译成功；人工桌面观感与用户当时的间歇性超时尚未实测复现。
