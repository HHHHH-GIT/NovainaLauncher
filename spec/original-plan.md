# iKunLauncher Next 实现方案

> 历史初始计划，保留设计背景。当前产品为 Novaina Launcher，实际技术栈为 .NET 9/WPF，已增加下载、整合包和 AI 等功能；当前约束见 [architecture.md](architecture.md)。本文件不是验收报告。

## 目标与技术选型

在 `F:\Projects\iKunLauncher Next` 创建 Windows Minecraft Java 版启动器，完成三种登录、本地版本识别、Java 自动选择、依赖补全和日志弹幕。第一版支持启动已有原版及模组版本，不包含版本安装中心。

- 使用 **C# + .NET 10 LTS + WPF**，采用 MVVM，分离界面、账户和启动服务。本机先在用户目录准备 .NET 10 SDK，不替换现有 SDK。[支持周期](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)
- 界面基础采用 **WPF UI 4.3.0**，使用其控件、图标与 Windows 材质能力，通过自定义主题实现 Apple 风格。[WPF UI](https://github.com/lepoco/wpfui)
- 启动核心采用 **CmlLib.Core 4.0.6**，微软认证采用 **CmlLib.Core.Auth.Microsoft 3.3.1**；使用 CommunityToolkit.Mvvm，固定依赖版本。[启动核心](https://www.nuget.org/packages/CmlLib.Core)、[认证库](https://www.nuget.org/packages/CmlLib.Core.Auth.Microsoft)
- 参考旧项目的认证流程和交互思路，重新实现服务与界面；保留旧项目原样。

## 界面与交互

- 默认窗口为 **1080×700**，允许调整尺寸，最小 **900×600**。完全自定义顶栏，仅保留最小化和关闭按钮；禁用最大化及标题栏双击最大化。
- 导航提供两种形态：展开时显示左侧图标与文字，收起时隐藏侧栏，将导航转移到顶栏小图标。两种形态共享当前页面，并记住用户选择。
- 页面设为“启动、版本、账户、日志、设置”。启动页突出当前账户、版本、自动选定的 Java 和启动按钮；高级参数收进设置或折叠区域。
- 采用奶白／烟灰玻璃材质、蓝色强调色、细边框和柔和阴影。窗口圆角约 20px，卡片圆角 16px；使用 Windows 系统字体和矢量图标。
- 默认跟随系统主题，支持浅色、深色切换。优先使用系统亚克力；材质不可用时降级为半透明或实色背景，保持可读性。
- 实现按钮悬停与按压、页面切换、侧栏展开、账户面板和启动进度动画。微交互约 100–180ms，页面与导航约 220–280ms；连续操作可中断并衔接动画。
- 尊重系统减少动画设置。图标提供悬停提示和键盘焦点；界面使用简短标签，详细原因放入错误详情或日志。

## 登录、版本与启动

- **离线登录**：输入玩家名，生成稳定的离线 UUID，支持保存与切换账户。
- **微软登录**：沿用参考项目的 Client ID，并提供高级配置入口。使用设备码流程，在持久登录面板展示验证码、复制和打开浏览器按钮；支持取消、过期、自动刷新，以及无游戏资格等错误。Client ID 当前可用性通过真实账号验证。[配置说明](https://cmllib.github.io/CmlLib.Core-wiki/en/auth.microsoft/xboxauthnet.game.msal/clientid/)
- **LittleSkin 登录**：使用固定端点 `https://littleskin.cn/api/yggdrasil`，支持角色选择、令牌验证与刷新。通过 authlib-injector 注入认证和皮肤服务，缓存经过校验的 JAR，并传入预取的服务元数据。[LittleSkin 文档](https://manual.littleskin.cn/yggdrasil/)、[启动器规范](https://yushijinhun.github.io/authlib-injector/en/launcher-technical-specification.html)
- 账户支持添加、切换和移除。令牌通过 Windows DPAPI 加密保存，不保存密码；日志和弹幕过滤密码、令牌及认证请求内容。
- 开发运行默认扫描当前项目根目录的 `.minecraft`；发布后默认扫描启动器所在目录的 `.minecraft`。用户可以指定父目录或直接选择 `.minecraft`，记住选择并提供刷新入口。
- 本地扫描不访问网络。通过核心解析版本 JSON、继承链、库和启动参数，识别已有 Forge、Fabric、NeoForge 等版本；损坏版本显示简短状态，不影响其他版本。
- 游戏目录默认使用共享根目录；若版本目录已有 `mods`、`saves` 或 `options.txt`，自动采用该版本目录作为隔离目录，并提供手动覆盖，避免遗漏既有配置。
- Java 扫描覆盖启动器 runtime、Minecraft runtime、`JAVA_HOME`、`PATH`、注册表和常见安装目录。后台验证版本及架构，设置超时、缓存和路径去重，不弹出控制台窗口。
- Java 需求优先读取继承后的版本元数据；旧版本使用明确的兼容映射，未知版本要求手动指定。优先选择匹配主版本、匹配架构且补丁较新的 Java，支持每版本覆盖。
- 缺少 Java 时显示所需版本，点击后从 Adoptium 下载对应 Windows x64 运行时，校验后存入启动器专用 runtime 目录，不修改系统环境变量。
- 启动流程统一为：验证账户 → 解析版本 → 选择 Java → 检查并补齐依赖 → 创建游戏进程 → 收集输出与退出状态。完整文件的离线启动不请求远程版本清单；缺失依赖无法下载时明确提示缺少项。
- 启动准备阶段支持取消、防止重复提交。默认保持启动器打开；关闭启动器不结束已运行的游戏。

## 服务接口与日志弹幕

- 建立账户、版本目录、Java、启动和日志服务；界面仅通过异步命令调用，不直接处理认证协议或拼接启动命令。
- 内部数据类型包括 `AccountProfile`、`VersionInfo`、`JavaRuntimeInfo`、`LaunchRequest` 和 `LauncherLogEvent`。启动请求固定账户、目录、版本和 Java，操作期间的界面切换不改变已提交请求。
- 启动状态统一为准备中、补全中、启动中、运行中、已退出、失败；网络和文件操作支持取消，耗时任务不阻塞 UI。
- 统一日志流接收启动器事件及游戏 stdout/stderr，同时供日志页、文件和弹幕消费。
- 弹幕提供“关闭、精选、全部”三档，默认精选关键阶段、警告和错误。精选模式合并重复进度；全部模式限速展示。
- 弹幕从右向左滚动，使用固定轨道与位移动画，最多同时显示 12 条，待显示队列最多 200 条。积压时优先保留错误；显示层的合并或丢弃不影响完整日志文件。
- 弹幕不拦截鼠标操作，登录弹窗打开时暂停展示。错误同时保留在页面状态中，日志页支持搜索、等级筛选、复制和导出。

## 验收与交付

- 自动化测试覆盖离线 UUID、版本继承及损坏 JSON、目录隔离、Java 版本选择与超时、认证刷新与取消、日志脱敏，以及弹幕积压控制；使用本地测试数据和模拟 HTTP 响应。
- 实测原版 Java 8／17／21／25 场景及已有 Forge、Fabric、NeoForge 版本；检查中文和空格路径、缺失依赖、无网络和只读目录。
- 通过真实账号验证微软登录、重启后刷新、LittleSkin 多角色选择与游戏内认证。需要用户完成网页授权；模拟测试不代替真实登录验收。
- 检查浅深主题、两种导航、125%／150%／200% DPI、自定义窗口按钮、动画连续切换和日志高频输入，确认弹幕不遮挡主要操作。
- 交付源码、构建说明、开源依赖声明及 **Windows x64 自包含发布包**，用户无需另外安装 .NET。Java 与游戏文件仍通过本地识别或下载获取。
